     COVER: live migration, which is the operation that justifies the entire cost of a second
     host, and the maintenance workflow built on it.
     WHAT IT IS: moving a running VM to another host with no downtime — memory copied
     iteratively while it runs, then a pause of milliseconds. STORAGE MOTION moves the disk
     too, between SRs, which is how you empty a storage array you are retiring.
     THE REQUIREMENTS THAT ACTUALLY BITE: compatible CPUs across the pool (and the cost of
     Series 1 · 25's host-passthrough decision arriving here), a network both hosts have, and
     shared storage unless you are moving the disk as well.
     MAINTENANCE MODE as the workflow: put the host into maintenance, watch every VM migrate
     off it, patch it, reboot it, take it out. THE WORKPLACE MOMENT, AND IT IS THE WHOLE
     BUSINESS CASE FOR A POOL: it is eleven o'clock on a Tuesday morning, there is a kernel
     security update, and the warehouse load does not stop and nobody is asked to work at
     midnight.
     THE HONEST LIMITS: a VM with a passed-through PCI device usually cannot migrate; a VM
