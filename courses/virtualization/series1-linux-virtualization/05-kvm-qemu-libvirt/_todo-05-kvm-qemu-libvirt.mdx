     COVER: three words people use as one, separated once and for good, because every
     confusing error message in Linux virtualization comes from not knowing which layer spoke.
       KVM      a KERNEL MODULE that turns Linux itself into a hypervisor. It is not a
                product you install; /dev/kvm either exists or your firmware has
                virtualization switched off. `grep -E 'vmx|svm' /proc/cpuinfo`, and
                `kvm-ok` on Debian.
       QEMU     the USERSPACE process that provides the virtual hardware — the disk
                controller, the network card, the display. One QEMU process per running VM,
                visible in `ps`, which surprises people the first time they see it.
       LIBVIRT  the MANAGEMENT LAYER — a daemon, an XML definition per domain, and `virsh`.
                It is what every tool in this course is really talking to, directly or by
                having reimplemented it.
     THE WORKPLACE POINT, and it justifies the episode: THIS IS WHAT PROXMOX IS. And what
     OpenStack is, and what most cloud providers are. Learning the three layers once means
     every KVM-based product afterwards is a UI over something you already understand.
     ALSO COVER: `virsh` as the vocabulary — domain, network, pool, volume — and where the
     XML lives, because reading a domain's XML is how you answer "what is this VM actually
     configured with" in every one of these products.
