       wonderful for exploration — and it CANNOT naturally express anything path-dependent:
       a stop that depends on where you got in, a position size that depends on current
       equity, an order that did not fill. It also makes look-ahead almost effortless, which
       is the real objection.
       EVENT-DRIVEN: a loop over time, one bar or tick at a time, with a strategy that can
       only see what has arrived. Slower, more code — and it is THE SAME SHAPE AS THE LIVE
       SYSTEM, which is the argument that decides it.
     THE RECOMMENDATION AND THE REASON: vectorised for the first look, event-driven for
     anything you would put money behind, AND THE SAME STRATEGY CODE RUNNING IN BOTH THE
     BACKTEST AND LIVE. If those are two implementations, they will diverge, and the
     divergence will be discovered with real orders.
     THE ARCHITECTURE TO BUILD: a clock, an event feed, a strategy that receives events, a
     portfolio, and a simulated broker — with the strategy having NO ACCESS to anything but
