     COVER: why an index is a different animal when the data is spread across machines. A
     LOCAL index lives beside its partition — cheap to maintain, and a query that does not
     name the partition has to ask every node. A GLOBAL index is itself distributed, so
     keeping it consistent with the writes is coordination you pay for on every write.
     THE CONSEQUENCE, and it is the practical takeaway: on several of these engines the
     advice is to model a second table instead of adding a secondary index. That reads as
     primitive to a relational reader and it is the honest answer to a real constraint.
