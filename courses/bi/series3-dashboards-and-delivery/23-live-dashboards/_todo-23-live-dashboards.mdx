      START WITH THE GATE            MOST "REAL-TIME" REQUESTS ARE NOT. Ask what decision gets made
                                     differently because the number is thirty seconds old rather than five
                                     minutes old. Usually none, and a refresh interval is the entire
                                     solution.
      THE ONE CASE THAT NEEDS PUSH   somebody is WATCHING the screen in order to act — an operations
                                     wallboard, a queue, a live event. If nobody is watching, nothing needs
                                     pushing.
      SCHEDULED REFRESH              re-run the query every N seconds. Simple, cacheable, and correct for
                                     almost every dashboard anybody has ever asked for.
      POLL A CHEAP CHECK             ask "has anything changed" — a max timestamp, a version — and re-run
                                     the expensive query only when the answer moved. The underused middle
                                     option, and it deserves the most airtime.
      PUSH                           websockets or server-sent events with a pub/sub channel behind them.
                                     Genuinely live, and now you own connection state, reconnection, and
                                     what a client disconnected for ten minutes sees when it returns.
      THE COST NOBODY PRICES         A LIVE DASHBOARD RUNS ITS QUERY FOREVER. A forty-second query on a
                                     five-second refresh is not a dashboard, it is a denial-of-service
                                     against your own warehouse — which is why this comes after 22. Pre-
                                     aggregate, then choose the interval, then cap how many people can have
                                     it open.
      SHOW WHEN THE DATA IS FROM     a dashboard that silently displays a stale number is worse than one
                                     that says "as of 09:14", and the timestamp costs nothing. 22 owns
                                     explaining why a number is stale; this owns showing that it is.
