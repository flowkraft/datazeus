      THE LAYOUT            file → ROW GROUPS → column chunks → pages. And the fact that
                            decides everything: THE FOOTER HOLDS THE METADATA AND IS READ
                            FIRST, so a reader knows what is in the file before reading any
                            of it.
      MIN/MAX STATISTICS    per row group and per page. This is why predicate pushdown
                            works at all — a whole row group is discarded without
                            decompressing a byte. Learn SQL, Series 3 · 18 taught filtering
                            early; this is what the file does with your filter.
      ENCODINGS             dictionary, run-length, bit-packing, delta — and the
                            distinction nobody draws: ENCODING IS NOT COMPRESSION. A
                            low-cardinality column becomes tiny because it is
                            dictionary-encoded, and snappy or zstd is applied on top.
                            ClickHouse's LowCardinality is the same idea in another product.

                            COLUMN-ORIENTED file stores a record containing arrays and
                            structs without losing its shape. Most readers have never
                            wondered how that is possible, and the answer is elegant.

    ── THE CONSEQUENCE THAT MAKES IT ACTIONABLE ────────────────────────────
    SORT BEFORE YOU WRITE. Min/max statistics only skip when values are clustered. Write
    the same rows in random order and every row group's range covers everything, so nothing
    is skipped and the file is no faster than a CSV with better compression. Series 2 · 15
    owns sort keys as a warehouse decision; this is why they exist at the file level.
    ROW GROUP SIZE is the second dial: too small and per-group overhead dominates, too
    large and there is nothing granular left to skip.
