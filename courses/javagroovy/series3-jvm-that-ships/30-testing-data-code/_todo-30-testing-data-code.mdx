    GOAL: decide what a data test runs against, and write tests that would actually have

    RE-SPINED 2026-09-02. This was "JUnit and Spock, and What Is Worth Testing", which led on

    THE FAILURE, and it is this track's selection rule exactly: a suite that runs against H2
    or another in-memory stand-in PASSES and the job fails in production — or worse, both
    pass and return different rows. Nothing throws. What genuinely differs:
      · UPSERT — ON CONFLICT and the MERGE spellings are not the same statement on a stand-in,
        so the one write you most want covered is the one you cannot cover
      · date/time and string functions, and casting rules — the quiet ones, because they
        return a DIFFERENT ANSWER rather than an error
      · JSON, sequences, identity-column behaviour
      · the whole dialect surface Series 2 · 30 (jOOQ) and 2 · 32 (MyBatis) exist to let you
        write. jOOQ's codegen needs the real schema; testing it elsewhere tests something else.

    THE SPINE IS TESTCONTAINERS: the test starts a real Postgres in a container, runs against
    it, throws it away. Same engine as production, no shared dev database, no cleanup ritual
    between developers.

    AND THE COSTS, HONESTLY, or this is an advert. Containers are slow to start, so a naive
    suite pays that per class — reuse and the singleton-container pattern are part of the
    lesson. And DOCKER IS NOT ALWAYS THERE: locked-down CI, corporate laptops, some build
    agents. That is the real reason teams pick H2, and an episode that does not say so is not
    describing the world the reader works in.

    THE RULE THE EPISODE ACTUALLY TEACHES IS A SPLIT, NOT A WINNER:
      IN-PROCESS (DuckDB, SQLite)   tests about YOUR LOGIC — the transform, the parsing, the
                                    shaping. Fast, no Docker, engine irrelevant.
      REAL ENGINE IN A CONTAINER    tests about BEHAVIOUR — dialect, migrations, generated
                                    SQL, round-trip counts. Anywhere the engine IS the subject.
    A reader who can say which of the two a given test belongs in has the skill.

    KEEP THE ORIGINAL JUDGEMENT, which was good and is not replaced: a transform and a parser
