     BATCH is not a transaction. A LOGGED batch gives atomicity across partitions — all or
     none, eventually — at a real cost in coordination, and it is NOT isolation: other readers
     see partial results while it runs. An UNLOGGED batch spanning partitions is simply a
     slower way to send several writes, and is an antipattern.
     WHERE BATCH IS RIGHT: several writes to the SAME partition, which is one operation on one
     node — and that is exactly the "one write feeds five tables" case from Series 1 · 20,
     done properly.
     LIGHTWEIGHT TRANSACTIONS: IF NOT EXISTS and compare-and-set, implemented with Paxos,
     costing several round trips. Correct, occasionally necessary, and not something to put on
