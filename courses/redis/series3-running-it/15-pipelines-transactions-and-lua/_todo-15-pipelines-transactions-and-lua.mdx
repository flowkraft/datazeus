       PIPELINING   send many commands without waiting for each reply. Purely a network win —
                    no atomicity — and usually the largest single performance improvement
                    available to an application talking to Redis.
       MULTI/EXEC   queued commands executed together. NOT a rollback transaction: if one
                    command fails the others still ran, because there is nothing to undo.
                    Say that plainly, because the word transaction sets a wrong expectation.
       LUA (EVAL)   a script that runs atomically on the server, which is how you do
                    read-then-write logic safely. Keep it short — it blocks everyone.
