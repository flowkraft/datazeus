    ── WHY THIS EPISODE, SPECIFICALLY ──────────────────────────────────────
    GOAL: change data on purpose, and be able to undo it.
    SQL: INSERT (single, multi-row, INSERT … SELECT), UPDATE … WHERE, DELETE … WHERE, BEGIN,
    COMMIT, ROLLBACK, INSERT … ON CONFLICT DO NOTHING / DO UPDATE.
    ON CONFLICT IS NOT OPTIONAL HERE — see the curriculum note above this episode. The
    failure that earns it: an import script run twice. Without ON CONFLICT the second run
    either duplicates every row or dies on the unique constraint, and the beginner's
    instinct is SELECT-then-INSERT, which is a race. DO NOTHING is the idempotent load;
    DO UPDATE is upsert in one statement. Portability (MERGE elsewhere) is Series 4 · 05's
    job, not this episode's — teach the PostgreSQL form and say the other spellings exist.
    PLACED LATE ON PURPOSE, and this is the reason: the failure mode of teaching UPDATE early is a
    learner who runs it without a WHERE. By here, filtering is second nature.
    Teach the SELECT-first habit: write the WHERE as a SELECT, look at the rows, then change the
    verb. BOUNDARY: isolation levels and locking are Data Ops; COMMIT/ROLLBACK basics are here.
