## Light, medium or heavy?

The shipping team is reviewing freight costs, and they want **every order labelled light, medium or heavy**: freight under 25 is light, under 60 is medium, and anything more is heavy.

With Series 1 alone, this takes three queries, one `WHERE` per band, and the three answers put together by hand. Even then the result is three counts, not a label on each order. This lesson adds the tool that does it in one query: **CASE**, SQL's if-then.

Every query below runs on the Northwind database on PostgreSQL. Type each one into CloudBeaver and compare the result with the table under it. If that is not set up yet, the [Learn Data](/docs/learn-data) guide gets it running.

## CASE: a value chosen row by row

{/* The same highlight as the video: the three branch lines, in grey. */}

```sql file=./scripts/freight-band-per-order.sql {3-5}
SELECT "OrderID", "Freight",
       CASE
         WHEN "Freight" < 25 THEN 'light'
         WHEN "Freight" < 60 THEN 'medium'
         ELSE 'heavy'
       END AS "Band"
FROM "Orders"
ORDER BY "OrderID"
LIMIT 6;
```

For every row, CASE checks each `WHEN` **from the top**. The first test that is true gives the row its value, and CASE stops there. If no test is true, the `ELSE` value is used. `END` closes the CASE, and `AS "Band"` names the new column.

It is an expression, like the calculated columns from the <a href="/academy/learn-sql/distinct-aliases-expressions" target="_blank" rel="noopener" className="font-medium underline underline-offset-4">aliases and expressions lesson</a>. The difference is that it chooses its value instead of calculating it.

## Count the bands

The new column can be grouped like any other. Use the same CASE with `GROUP BY "Band"`:

{/* The same highlight as the video: the GROUP BY line, in grey. */}

```sql file=./scripts/orders-per-band.sql {8}
SELECT CASE
         WHEN "Freight" < 25 THEN 'light'
         WHEN "Freight" < 60 THEN 'medium'
         ELSE 'heavy'
       END AS "Band",
       count(*) AS "Orders"
FROM "Orders"
GROUP BY "Band"
ORDER BY min("Freight");
```

| Band   | Orders |
| ------ | ------ |
| light  | 16     |
| medium | 34     |
| heavy  | 29     |

16, 34 and 29 add up to 79, every order in the table. The label the query made up is the thing it groups by. `ORDER BY min("Freight")` sorts the bands by the smallest freight in each, so light comes first instead of in alphabetical order.

PostgreSQL and DuckDB both let `GROUP BY` use the name `"Band"` from the `SELECT`. Some databases do not, and there you repeat the whole CASE in the `GROUP BY`.

## The first true WHEN wins

Now swap the first two `WHEN` lines, so medium is tested before light:

{/* The same highlight as the video: the two swapped lines, in red. */}

```sql file=./scripts/orders-per-band-whens-swapped.sql {2-3}#err
SELECT CASE
         WHEN "Freight" < 60 THEN 'medium'
         WHEN "Freight" < 25 THEN 'light'
         ELSE 'heavy'
       END AS "Band",
       count(*) AS "Orders"
FROM "Orders"
GROUP BY "Band"
ORDER BY min("Freight");
```

{/* The same highlight as the video: medium in terracotta — it swallowed the light orders. */}

There are no light orders at all, and medium went from 34 to 50. The 16 light orders are still in the table, and their freight did not change. What changed is the order of the tests: **under 25 is also under 60**. The first `WHEN` now asks "under 60?", every light order answers yes, and CASE stops there. The light test is never reached.

There is no error and no warning. The result simply has one band fewer. So **write the narrow tests first**: a wide test above a narrow one catches its rows before the narrow one is checked.

## No ELSE means NULL

Finance only cares about heavy orders, freight over 50. So the CASE gets one `WHEN` and no `ELSE`:

{/* The same highlight as the video: the CASE's one WHEN, in grey. */}

```sql file=./scripts/heavy-label-no-else.sql {2-3}
SELECT CASE
         WHEN "Freight" > 50 THEN 'heavy'
       END AS "Label",
       count(*) AS "Orders"
FROM "Orders"
GROUP BY "Label"
ORDER BY "Label" NULLS LAST;
```

{/* The same highlight as the video: the NULL row in terracotta. */}

<div className="[&_tbody_tr:nth-child(2)]:bg-[rgb(var(--hl-fault)/var(--hl-row))] [&_tbody_tr:nth-child(2)_td]:font-bold [&_tbody_tr:nth-child(2)_td]:text-[rgb(var(--hl-fault-ink))]">

| Label    | Orders |
| -------- | ------ |
| heavy    | 37     |
| `[NULL]` | 42     |

</div>

37 orders are heavy, and **42 orders are labelled NULL**. A CASE with no `ELSE` returns NULL for every row that no `WHEN` matched. It does not look harmful here, because the 42 are still counted. The trouble starts when a query tests the label.

### How many orders are not heavy?

The label is made in a subquery in `FROM` (the <a href="/academy/learn-sql/subqueries" target="_blank" rel="noopener" className="font-medium underline underline-offset-4">subqueries lesson</a>), because a `WHERE` cannot see a name given in the same query's `SELECT`. Then the `WHERE` keeps the orders whose label is not 'heavy':

{/* The same highlight as the video: the WHERE, in red. */}

```sql file=./scripts/not-heavy-no-else.sql {7}#err
SELECT count(*) AS "Not heavy"
FROM (SELECT CASE
               WHEN "Freight" > 50
               THEN 'heavy'
             END AS "Label"
      FROM "Orders") AS t
WHERE "Label" <> 'heavy';
```

| Not heavy |
| --------- |
| 0         |

Zero, although 42 orders are not heavy. Every one of them is labelled NULL, and this is the rule from the <a href="/academy/learn-sql/null-and-three-valued-logic" target="_blank" rel="noopener" className="font-medium underline underline-offset-4">NULL lesson</a>: NULL is not unequal to 'heavy'. The comparison `NULL <> 'heavy'` is **unknown**, and `WHERE` keeps only rows where the test is true. All 42 are dropped.

### Write the ELSE

Give every other order a real label:

{/* The same highlight as the video: the ELSE line, in green. */}

```sql file=./scripts/not-heavy-with-else.sql {5}#good
SELECT count(*) AS "Not heavy"
FROM (SELECT CASE
               WHEN "Freight" > 50
               THEN 'heavy'
               ELSE 'standard'
             END AS "Label"
      FROM "Orders") AS t
WHERE "Label" <> 'heavy';
```

| Not heavy |
| --------- |
| 42        |

One line, and the 42 orders are back.

## CASE inside SUM: a column for each status

Now the most useful thing CASE does. A manager wants, for every country, **how many orders there are and how many are still waiting**, side by side, one row per country.

That is two counts with two different conditions, and one query has only one `WHERE`. The way around it is to move the condition into the column:

{/* The same highlight as the video: the SUM(CASE …) lines, in grey. */}

```sql file=./scripts/orders-and-unshipped-per-country.sql {3-4}
SELECT "ShipCountry",
       count(*) AS "Orders",
       SUM(CASE WHEN "ShippedDate" IS NULL
           THEN 1 ELSE 0 END) AS "Unshipped"
FROM "Orders"
GROUP BY "ShipCountry"
ORDER BY "Orders" DESC, "ShipCountry";
```

Germany has 32 orders, and 10 of them are still waiting. `SUM` adds numbers, so how did it count? The CASE turns every waiting order into a 1 and every shipped order into a 0, and `SUM` adds the ones. The result is a count of waiting orders, **without a `WHERE`**, next to the count of all orders.

You can add as many of these columns as you need, one per status, all in the same `GROUP BY`. This is how a report with a column for each status is built.

### The same, with count

You will also see it written with `count`, and there the missing `ELSE` is on purpose:

{/* The same highlight as the video: the count(CASE …) lines, in green. */}

```sql file=./scripts/unshipped-counted-with-count.sql {3-4}#good
SELECT "ShipCountry",
       count(*) AS "Orders",
       count(CASE WHEN "ShippedDate" IS NULL
             THEN 1 END) AS "Unshipped"
FROM "Orders"
GROUP BY "ShipCountry"
ORDER BY "Orders" DESC, "ShipCountry";
```

Shipped orders get NULL, `count` of a column skips NULLs, and the result is the same table: Germany still has 10. In the filter above, the missing `ELSE` was a bug. Here it does the counting. The difference is whether you meant the NULLs.

### Per employee

The same method works for any group. Join the orders to `"Employees"`, and count each person's orders and how many of them are still waiting:

{/* The same highlight as the video: the SUM(CASE …) lines, in grey. */}

```sql file=./scripts/waiting-per-employee.sql {3-6}
SELECT e."FirstName",
       count(*) AS "Orders",
       SUM(CASE
             WHEN o."ShippedDate" IS NULL THEN 1
             ELSE 0
           END) AS "Waiting"
FROM "Orders" o
JOIN "Employees" e
  ON e."EmployeeID" = o."EmployeeID"
GROUP BY e."FirstName"
ORDER BY e."FirstName";
```

## The short form

When every `WHEN` compares the same column with a value, the column can be written once, after `CASE`:

{/* The same highlight as the video: CASE "ShipVia" and its first WHEN, in grey. */}

```sql file=./scripts/shipper-names-by-case.sql {1-2}
SELECT CASE "ShipVia"
         WHEN 1 THEN 'Speedy Express'
         WHEN 2 THEN 'United Package'
         WHEN 3 THEN 'Federal Shipping'
       END AS "Shipper",
       count(*) AS "Orders"
FROM "Orders"
GROUP BY "Shipper"
ORDER BY "Shipper";
```

| Shipper          | Orders |
| ---------------- | ------ |
| Federal Shipping | 26     |
| Speedy Express   | 26     |
| United Package   | 27     |

It works, but these names are already stored in the `"Shippers"` table, and a join reads them from there:

```sql file=./scripts/shipper-names-by-join.sql
SELECT s."CompanyName" AS "Shipper",
       count(*) AS "Orders"
FROM "Orders" o
JOIN "Shippers" s
  ON s."ShipperID" = o."ShipVia"
GROUP BY s."CompanyName"
ORDER BY s."CompanyName";
```

It returns the same 26, 26 and 27. The join is better here: when a shipper is renamed, the table changes and the query does not have to. **CASE is for labels that nobody stored**, such as light, medium and heavy. If the label already lives in a table, read it from the table.

## COALESCE is a CASE

The <a href="/data-academy/learn-sql/null-and-three-valued-logic" target="_blank" rel="noopener" className="font-medium underline underline-offset-4">NULL lesson</a> used `COALESCE` to put a stand-in where a value is missing. It is a short way of writing a CASE: when the value is NULL, use the stand-in; otherwise use the value.

{/* The same highlight as the video: COALESCE and the CASE's three lines, in grey. */}

```sql file=./scripts/region-coalesce-and-case.sql {2,4-6}
SELECT "CompanyName",
       COALESCE("Region", '(none)')
         AS "With COALESCE",
       CASE
         WHEN "Region" IS NULL THEN '(none)'
         ELSE "Region"
       END AS "With CASE"
FROM "Customers"
ORDER BY "CustomerID"
LIMIT 4;
```

| CompanyName                        | With COALESCE | With CASE |
| ---------------------------------- | ------------- | --------- |
| Alfreds Futterkiste                | (none)        | (none)    |
| Ana Trujillo Emparedados y helados | (none)        | (none)    |
| Antonio Moreno Taquería            | (none)        | (none)    |
| Around the Horn                    | (none)        | (none)    |

The two columns are identical, and they stay identical for all 25 customers.

## Three rules for CASE

1. **The first true `WHEN` wins.** Put the narrow tests first.
2. **Write the `ELSE`**, unless the NULLs are the point. A row that no `WHEN` matches gets NULL, and NULL fails every comparison, including "not equal".
3. **`SUM(CASE …)` gives one column per status**, all in the same `GROUP BY`.
