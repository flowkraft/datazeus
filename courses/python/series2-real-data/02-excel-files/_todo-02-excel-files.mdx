    ── THE FOUR DEFECTS, AND WHY THEY CANNOT LIVE IN A CSV ─────────────────
    This is the whole reason the episode is worth writing and not a footnote on 00.
    None of these is possible in a text file, so a reader who has done the CSV episodes
    has met none of them:

      1. A TITLE ROW ABOVE THE HEADER. "Q3 Orders — Confidential" in A1, the real
         header on row 3. read_csv has no equivalent problem; here the default gives
         you a frame whose columns are called `Unnamed: 1`.
      2. MERGED CELLS. One "Customer" heading spanning two columns. openpyxl reports
         the value once and NaN for the rest of the span.
      3. A DATE THAT ARRIVES AS 45123. Excel stores dates as days since 1899-12-30.
         Read the column as a number and you get a five-digit integer that is a
         perfectly plausible order ID.
      4. A NUMBER STORED AS TEXT. The leading apostrophe is invisible in Excel, and the
         column comes through as object dtype — so .sum() concatenates instead of adding,
         which is the worst failure in the file because it produces an answer.

    DATASET: generated (tier 3), and the reasoning is worth keeping. An .xlsx is a zip of
    XML, so committing one breaks tier 2's entire rationale — that a reviewer can see the
    defect in a diff. Instead the four defects are AUTHORED in a generator script, which
    is reviewable text, and the binary is built from it:
        python datasets/generated/make_messy_excel.py
